# 已知取舍

- `.png` 导出依赖系统里装好的 `rsvg-convert`(终端没法把字体栅格化);没有它会给一个明确的
  错误。
- `.dot` 导出是有损的:同名节点会合并,`via`/`layer`/`terms` 在 Graphviz 里是别的意思,
  相机状态也表达不出来。
- `--ascii` 用形状信息换可移植性:所有拐角、T 形接点与交叉都变成 `+`,双线/粗线框退化成单线。
  只在终端画不了制表符时用它,不要当风格选择。
- 编辑命令与输入仍然要求 `1:1`(会先切回,并锚在光标上);`:layout` / `r` 与鼠标拖框在任意
  缩放下都能用。因为文档是整数格,2x 视图下每个格子要占两个鼠标格,0.5x 视图下移动一个鼠标格
  会跳两格。
- 缩放只缩放**几何**,字形在绘制文字时始终是一字符一格。`f` / `F` 最多铺到 `1:1`;再往外
  只会把框拉开、字形大小不变。低于 60% 时文字完全不画(状态行标 `LOD`),低于 30% 时框变成
  实心块,所以很小的缩放只适合当导航总览,不是用来读的。
- 打开文档会像按 `0` 一样重置视图:`1:1`,以画面为中心。`.gtui` 里存的 `zoom` / `center`
  仍然会写,也仍然供 `--dump` 与图片导出使用,但交互式打开不会恢复它们;要看全就按 `F`。
- `cargo clippy --all-targets` 没有警告;两个走线原语参数很多,显式 `allow(too_many_arguments)`,
  理由写在注释里。
- `via` 折点是**画布坐标**:换布局后别的都动了、折点不动,所以得手动重设。
- 虚线/点线只断开直线段;拐角与交叉处永远是实线(否则看不出线在哪儿拐);已经被实线占掉的
  格子优先保持实线。
- 隔离视图(`E`)里,可见的边会重新画在框、文字与标签之上;藏起来的边保留原来的端口与路线,
  所以可见边可能在某个已经不再绘制的框原来的位置留下缺口。可见邻居上的端口保持所属边的颜色,
  藏起来的边完全不写端口字形。这层覆盖只重画这条边真正占有的格子,所以已经被别的边赢走的
  交叉格不会被动。
- 两条边永远不会合成 `┼` / `├`:一格只显示一条边自己的笔画,另一条到那里就结束(交叉读作
  `─│─`,不是 T 形接点)。先画的边在上面;选中一条边(在它覆盖的格子上反复点击轮选,或用
  `Ctrl-e`)会把它抬到最上面,被盖住的那条就翻上来。`E`(隔离)同样抬高可见边,所以可见边
  不会被穿过它的边切碎。
- 箭头永远在最上层:别的边穿过它的格子时,箭头保留自己的颜色而不是被丢掉,而且一格仍然只放
  一个箭头。只有节点能盖过它们。
- 没有图例面板了(v9 移除)。键只能画成内容(`none` 或带框的框、一条样例边、分组颜色),于是
  它会参与布局、命中测试与选区;要它原地不动就用 `geo`,或者在布局跑完之后再摆。旧的
  `legend` 数据读入即丢弃,绝不迁移。
- 斜体取决于终端支持(`Modifier::ITALIC`);有些终端会渲染成普通文字或反显。
- 存盘会把节点 id 改写成它的 label:用了单独 `label=` 的图,存一次盘后旧 id 会挪进 `terms`。
- 星形扇按**几何**捆扎辐条,不靠显式折点:一列最上/最下的叶子仍可能从竖直端口出去(端口侧
  按两框边界最近的一对来选,而这片叶子离中心行有 `dy` 的距离),于是会多画一个围着这一列的
  括号。想要整齐版本,可以用 `examples/limits/star40.gtui` 里手工摆了 `via` 并钉住侧面的
  那份。
- 走线只有正交:45 度的边在屏幕上变成一个 L;没有斜线笔画(`╱ ╲ ╳`),因为东亚字符宽度
  不可靠。
- `Ctrl+G` 的外部编辑器通过 `sh -c` 启动,需要 Unix shell;Windows 版能跑,但按这个键会提示
  不可用。
- `○ ◎ ─` 这类字形在某些中文字体里是两格宽,会把画面挤歪。
- 节点没有形状与尺寸概念,标签也没有引导线;位置冲突时标签直接丢掉。两个 `none` 框在屏幕上
  重叠时也一样:光标下的框保留文字,另一个整段文字都不画(画成半覆盖会把宽字符变成空白)。
- `layered` 是 Sugiyama-lite:分层、重心排序、断回边都有。布局会记下每个节点所在的行,相邻行
  之间的边总是从下侧出、从上侧进,所以一个 rank 读起来是一条竖直通道;但没有最小化交叉的正交
  布线器,也没有显式的轨道分配(通道用哪些列取决于端口对齐与加权代价,不是通道规划),所以很
  宽的 rank 仍可能拉出很长的横线。
- 走线是逐条贪心的:每条边按"已经画出来的东西"挑最便宜的路径(长度 + 拐弯 + 交叉 + 复用别的
  边的笔画,复用权重最高)。绘制前会先跑一遍规划,所以每条边至少能看到它前面那些边的规划路线
  (软惩罚,每格 18,比已经画在屏幕上的笔画 40 轻),绘制时再照着规划走;没有拆线重布的循环,
  所以后面的边仍可能落到比联合规划更差的走廊里,早规划的边也会占掉后面边需要的走廊。完全找不到
  路径时(墙比搜索窗口和边框都高),退回一段被裁掉的腿。
- 一帧只跑一轮走线:规划一遍,绘制照着走。规划结果有缓存(四个槽),只要文档修订号、几何、
  缩放、视口原点以及影响画哪些边的视图开关都不变就一直有效;所以移动光标、选择、开菜单或在
  两个已经渲染过的标签页之间切换是免费的,而平移、缩放或编辑会重新给那份文档走线。
- `geo` 要求每个节点都有坐标;没有就退回 `force` 或 `layered`。
- 规模:6000 个没有坐标的节点在 `force`(release)里大约 3.5 秒;再大就靠迭代上限兜住。
