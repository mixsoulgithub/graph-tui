# 文档格式 `.gtui`

原生文档是一个 JSON 对象;`type` 用于自校验,`unit` 永远是 `cell`:

```json
{
  "type": "graph-tui",
  "version": 10,
  "source": "graph-tui 0.14.0",
  "unit": "cell",
  "groups": [{"id": "g0", "label": "", "color": "#4c8ef8"}],
  "layers": [{"name": "", "order": 0}],
  "boxes": [
    {"id": "b1", "at": [10, 4], "size": [9, 3], "style": "rounded",
     "color": null, "fill": "#1b2440", "layer": "", "terms": ["central", "zx"],
     "edge": null},
    {"id": "b2", "at": [30, 4], "size": [8, 1], "style": "none",
     "color": null, "fill": null, "layer": "", "terms": [], "edge": "e1"}
  ],
  "texts": [
    {"id": "t1", "text": "Central\nsecond line", "at": [11, 5], "box": "b1", "color": null,
     "bg": null, "align": "center", "layer": ""}
  ],
  "edges": [
    {"id": "e1", "from": "b1", "to": "b2", "dir": "both", "group": "g0",
     "style": "solid", "color": null, "bg": null, "corner": "sharp",
     "from_side": "auto", "to_side": "auto", "head": "auto",
     "via": [[12, 5], [12, 9]], "layer": ""}
  ],
  "view": {"center": [20, 10], "zoom": 1.0, "layout": "layered", "cursor": [11, 5],
           "focus": [], "labels": false, "lang": "zh", "layer": null,
           "side": 2.0, "cycle": null, "orientation": "auto",
           "notes": true},
  "regions": []
}
```

要点:

- 框、文字、边是三种记录;框与文字**严格一对一**,一个文字永远只属于一个框。
- 坐标是整数格,`at` 是**左上角**。`style` 有六个取值:`single` / `rounded` / `double` /
  `heavy` 画框;`point` 占一格、画一个节点字形;`none` **什么都不画**,那块地方只有文字
  (宽度跟最长行,高度跟行数)。边仍然绕着它走,但不会在它上面画 T 形接点或箭头,箭头落在
  紧挨着它外面的那一格。端口仍然按边框规则走:一个节点上的多条边各自取自己的进/出点
  (只是不画出来),所以永远不会堆到同一格。**`style` 可以省略,默认 `none`**:没有样式的
  节点就是一行文字(`i` / `:new` / headless 的 `add_box` 默认都建这个)。
- 文字可以**多行**:`\n` 分行;`\r` / `\t` 一律拒绝。框会跟着行数长(`none`:高 = 行数,
  宽 = 最长行;带框:高 = 行数 + 2,宽 = 最长行 + 2,至少 4 宽 3 高)。行内样式是 markdown 的
  `**粗体**` 与 `*斜体*`(粗体里可以套斜体;没闭合的记号按普通文字处理);它们与对齐逐行
  生效。点节点只有一个名字,不能换行。规范形式不带末尾空行(编辑器桥接只剥掉一个末尾 `\n`;
  中间的空行保留);`"\n"` 是两行。
- 读入时会校验一切:未知键、重复键、重复 id、悬空引用、未知图层、非整数坐标、一个框上两个
  文字,以及放不进框的文字(`lines > height - 2` 或 `longest line > width - 2`),全部连同
  JSON 路径一起拒绝。
- 颜色是互相独立的层:`box.color` 是**边框**,`box.fill` 是**内部填充**(对点节点和 `none`
  无效),`text.color` 是**字形**,`text.bg` 是**文字背景**(只铺在字形格上,优先于 `fill`),
  `edge.color` 是**线**,`edge.bg` 是**线的背景**(只铺在这条边经过的格子上)。`text.bg` /
  `edge.bg` 可省略(没有这个键的旧文件照样能读),也接受 `null`。`text.align` 是
  `left|center|right`;左右留白只有在框比文字宽时才看得见。
- `edge.dir` 是四态 `none|forward|back|both`(不再只是有向/无向);`edge.corner` 是
  `rounded|sharp`。默认值分别是 `forward` 与 `rounded`。
- `edge.head` 决定这条边自己的箭头字形:`auto`、`ascii`(`^ v < >`)、`arrows`
  (`↑ ↓ ← →`)或 `triangles`(`▲ ▼ ◀ ▶`)。`auto` 是旧文件拿到的值,也是大多数边应该
  保持的值:全局 `--arrow` / `[prefs] arrow` 仍然决定这些边。想改单条边,用右键菜单
  (`arrowhead`)或 `:head triangles`;新边会像其他边样式一样继承上一次的选择。格式版本是 10。
- 边可以**连接节点自身**(`from` 等于 `to`):画成一个小钩,从一侧出去、从相邻一侧回来,
  箭头在回来的那端。它不算一条"线"(不串成序列),布局也不会给它分层,但能选中、能用
  `:style` / `:text` 改样式、也能像别的边一样导出。
- `view` 只是视图状态(中心、缩放、光标格、聚焦、图层、语言、朝向…);它不影响几何,存盘时
  **缩放永远不会乘进坐标**。`view.cursor` 在 v2 里是 `[x, y]` 格子(旧文件里的框 id 会转成
  那个框的文字原点;存一次盘就升级)。顶层 `version` 是 10;1 到 9 版也能读(v4 的
  `edge.label` 会转成绑在这条边上的注释框;v5 的注释框与 v6 的多行文字结构相同;v7 加区域;
  v8 加显式边侧面;v9 移除图例;v10 加 `edge.head`,旧文件缺这个键,按 `auto` 读)。
- **v9 移除了图例。** `version: 8` 的文件可能还带顶层 `legend` 对象和 `view.legend`;
  两者都会读入然后**丢弃**(键被接受,只是为了让旧文件能打开,内容不做迁移,因为没有可靠
  办法把面板的一行映射成框)。存盘写 v10,两个键都没有。想要画面里有键,就画成内容:纯文字
  (`none`)框、一条展示线型的短边、分组颜色,并用 `geo` 布局让它们别动。
- 边注释是**绑在边上的文本框**:一个 `style: none` 且带 `"edge": "<边 id>"` 的框。文字就是
  注释,框自己的 `at` 就是它的位置(不做逐帧摆放)。严格一对一:一条边最多一个注释框,一个框
  最多绑一条边。删边会连注释框一起删(一步撤销)。渲染从不会移动它;选中边时按 `i` 创建
  (建议位置 = 两个中心的中点右移一格,避开别的框,只算一次),`:relabel [all]` 重新锚定。
  它的文字颜色默认跟着边。开关是 `view.notes`(缺键按 `true` 读):关掉时不画、不算障碍、
  不占空间、也点不到。
- 存盘先写 `.tmp` 再改名;校验失败绝不会覆盖原文件,同一份文档存两次得到完全相同的字节。

### 导入 `.dot` / `.canvas`

- `.dot` 按 Graphviz 子集解析后转成原生格式:带框节点得到按文字定尺寸的框,点节点变成
  `1x1` 的点;带度量的 `pos` 在这条路径上一次性投影成格子(只有那里 `geo` 才有意义)。节点
  样式:`box=` 优先;否则识别 Graphviz 的 `shape=point`(点)与 `shape=none|plaintext`
  (纯文字);都没有就默认 `none`。导出时点节点写 `shape="point"`,其他样式写自定义的
  `box=` 键。`.dot` 转义:`\n` / `\l` / `\r` 都表示换行,`\\` / `\"` 反转义,其他 `\x`
  保留反斜杠(以前会被吞掉);导出把换行写成 `\n`。节点名进 `terms`,`label` 变成文字。
  没有 `pos` 的 `.dot` 导入时排一次布局(否则所有节点都挤在原点)。样式属性用 Graphviz
  会忽略的自定义键:`fill`、`align=left|center|right`、`corner=rounded|sharp`。边方向认
  `->` `<-` `--` 与 `dir=none|forward|back|both`(`dir=<name>` 优先)。
- `.canvas`(Obsidian)按每格 8x16 像素换算;canvas 没有方向语义,所以每条边导入后都是
  `forward`。
- 两种格式都**只作导入**:`.gtui` 才是可编辑的源。
- 导入之后没有原生源路径:**第一次 `w` 会在输入文件旁边写 `<stem>.gtui`**,原 `.dot` 不动。
- `.dot` 导出只走显式的 `--export x.dot` / `:export x.dot`;文件头会说明这是有损视图,
  每一项有损都会报告。
- 所有路径参数(`:w` / `:e` / `:export`,`--file` / `--export`)都展开开头的 `~`,
  缺少的父目录会**自动建出来**(`:w ~/figs/a/b.gtui` 会把目录一并建好)。

两个版本号,别混:

- **crate 版本**(`Cargo.toml` 里的 `version`、`graph-tui --version`)给程序本身定版本;
  现在是 0.14.0。
- **`.gtui` 格式版本**(文件里的 `"version"`)给文档格式定版本;现在是 10。只有结构性变化才升
  (v1 光标=框 id -> v2 光标=格子 -> v3 图例 -> v4 边标签 -> v5 注释=绑定的框 -> v6 多行
  文字 -> v7 区域 -> v8 显式边侧面 -> v9 移除图例 -> v10 逐边箭头),旧版本永远能读。
  两者互不相关。

## 区域(v7)

`regions` 是顶层的类 cluster 框数组。区域自己没有坐标:它的矩形是成员的包围盒加 `padding`
(并且会加宽以放下 `label`),所以框一动它就跟着动。

```json
"regions": [
  {"id": "r1", "label": "connection setup", "color": "#22b46a", "style": "rounded",
   "layer": "", "padding": 1, "members": ["b1", "b2"], "collapsed": false}
]
```

- `members` 是框 id 或其他区域 id;一个框最多属于一个区域,嵌套区域不能成环。两者在载入时
  都会拒绝。
- `style` 必须是带框样式(`single` / `rounded` / `double` / `heavy`)。
- 收起的区域画成一个小标题条,带 `…` 记号;它的成员框与碰到成员的边都不画(数据还在)。
  收起只影响显示。
- 区域画在边与框下面,所以永远不会盖住文字;边可以穿过区域边框。v7 里光标不拾取边框与标题
  (命令作用于光标框所在的区域,或显式给 id)。
- v7 之前的文件没有 `regions` 键,按空列表载入;存盘永远写 v10。

## 边端口(v8)

一条边可以钉住它从框的哪一侧出去 / 进入:

```json
{"id": "e1", "from": "b1", "to": "b2", "from_side": "left", "to_side": "up"}
```

- 取值:`auto`(默认,显式写出)/ `left` / `right` / `up` / `down`。`auto` 保持以前的行为:
  侧面由两个中心的差来选。
- 钉住的侧面只影响这一个端点;另一端可以仍然是 `auto`。
- 如果钉住的侧面**背对**另一个框(另一个框完全在它后面,边走线得绕一圈),就忽略这个钉法,
  该端点自动选侧面。只是不是最短路(比如目标在右下,却钉了 `up`)仍然照办。
- 点节点没有边框,所以对它们钉侧面会被忽略(设置时 TUI 会提示);`none` 节点有虚拟边框,
  会遵守。
- 每个边的端点在那个侧面上各占一格,而不是共用一两个锚点:格子的选法是对齐另一端(所以两个
  面对面的框会在同一行或同一列对齐),并尽量靠近内容中心。边按文件顺序分配,所以加一条边
  不会移动它前面那些边的端口。
- 一个侧面可能没有格子了。少于两格的侧面(一行高的 `none` 节点,或从左右看只有三行的框)
  会把整组挪到有空间、且朝向正确的侧面;否则只挪多余的端点。挪走的箭头会选"外侧格离另一个框
  最近"的侧面(背对它的是最后选择),而不是简单地顺时针下一个。没有箭头的端点也可以并入最近的
  已有接点,字形画成 `T`。所有侧面都没有空格时,端口退回侧面中心。
- 一个侧面提供多少格来自**边框**,不是来自文字:一个 18 行高、标签只有一行的框,左右两边
  仍然各有 16 格。
- 一条边如果**相对它两端的框**很短(`edge distance <= 最大框边长`,两端都是 `auto`),就会
  试遍 16 种侧面组合,优先能直线走通的那组,所以大框旁边的小框会沿同一根轴进出。长边仍按
  普通规则;钉了 `from_side` / `to_side` 的退出这套。
- 侧面满了要挪端点时,按"挪一下能换来多少"来挑,优先挪普通线而不是箭头(箭头承载边的语义,
  线还能并到相邻的线里)。显式 `from_side` / `to_side` 永远不挪。一行高的 `none` 节点保留
  它只有一格的左右侧面,让几条普通线共用一个格,而不是被挪到上/下。
- 多条边钉到同一侧时,按顺序填那一侧的空格(沿用现有的 `border_slot` 规则);箭头仍然独占
  一格。
- TUI 里:选中边,用 `:fromside` / `:toside` / `:port from=… to=…`,或者打开样式菜单(`s`
  或右键)-> **ports** -> 起点 / 终点 -> 侧面;菜单实时预览,应用只产生一步撤销。
- v8 之前的文件所有边都按 `auto` 载入;存盘永远写 v10。
